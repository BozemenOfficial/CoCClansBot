# Проверка способов подключения

Этот стенд сравнивает сетевые маршруты. Настоящий ключ Supercell, API Token игрока, токен Telegram и рабочая D1 ему не передаются. Рабочий бот использует отдельный `wrangler.toml` в корне проекта.

Результат последнего опыта и выводы: [connection-options.md](../docs/connection-options.md).

## Повторить сетевой опыт

Нужны Node.js 24, pnpm, curl и авторизация Wrangler в своём аккаунте Cloudflare.

1. Подготовьте приватный `.env.connection-lab-secrets.json` с единственным полем `LAB_SECRET`: случайная строка из 64 шестнадцатеричных символов. Файл игнорируется Git. В нём не должно быть ключей других сервисов.
2. Разверните отдельный Worker:

   ```bash
   pnpm exec wrangler deploy --config lab/wrangler.toml --secrets-file .env.connection-lab-secrets.json
   ```

3. В приватном `.env.connection-lab-client` задайте `CONNECTION_LAB_URL` адресом созданного Worker и `CONNECTION_LAB_SECRET` тем же секретом. В файле только эти две переменные.
4. Запустите:

   ```bash
   pnpm probe:connections
   ```

   Скрипт выполнит пять кругов запросов из текущей машины и из Worker. Проверяются профиль, клан и два POST с разными заведомо тестовыми игровыми токенами. Результаты сохраняются в `docs/evidence/connection-probes.json`. Ключи API не принимаются этим скриптом.

5. Удалите тестовый Worker после опыта:

   ```bash
   pnpm exec wrangler delete coc-clans-connection-lab --config lab/wrangler.toml
   ```

   Удаляется только отдельный тестовый Worker. Имя работающего бота — `coc-clans-bot`.

Для исследования своей сети можно запускать только отдельные пробы через `/` с параметрами `target=official|royaleapi|clashking|egress`, `operation=profile|clan|verify_a|verify_b` и заголовком `X-Lab-Secret`. Произвольный URL передать нельзя. Ответы самого стенда имеют `Cache-Control: no-store`.

## Проверить свой gateway

```bash
pnpm probe:gateway
```

Скрипт поднимает `gateway/server.ts` на случайном порту `127.0.0.1`, проверяет авторизацию и разрешённые маршруты, выполняет реальные запросы в Supercell с заведомо недействительным ключом и закрывает сервер. Ничего не разворачивается на ПК пользователя или во внешнем VPS. Результат — `docs/evidence/gateway-probes.json`.

## Границы измерений

- `403 Missing authorization` означает доступность HTTP-маршрута, а не успешное чтение профиля.
- `401 Authentication token missing` у ClashKing означает, что для выбранного маршрута нужна его авторизация.
- Два разных тестовых токена без ключа не проверяют правильность `verifytoken`: запросы не прошли авторизацию.
- Для Worker `elapsed_ms` измеряется внутри Worker вокруг внешнего запроса. Для машины и gateway это время запроса со стороны клиента. Между этими группами нельзя делать прямой вывод о скорости рабочих профилей.
- Один и тот же адрес в пяти ответах IP-echo не является гарантией постоянного IP. Адрес для другого назначения может отличаться.
- Полные исключения, тела запросов, заголовки авторизации и секреты в артефакты не записываются. Из ответа сервиса сохраняются только статус, короткие диагностические поля и заголовки кеширования.
