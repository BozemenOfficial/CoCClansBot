# Ротация секретов

Ключи, переданные в переписке, следует заменить. Значения не публикуются в Git или чате.

1. Cloudflare: владелец создаёт новый API Token с минимальными правами Workers Scripts Edit, D1 Edit и Account Settings Read. Сохраняет его в секретном окружении. Проверяет чтение аккаунта и доступ к нужным Worker/D1. После успешной проверки отзывает старый токен. Это не требует остановки бота.
2. Clash API: владелец создаёт новый ключ для исходящего IP используемого RoyaleAPI. Проверяет запрос реального профиля, сохраняет новый COC_API_TOKEN через Wrangler secret, проверяет профиль Mini App и синхронизацию. Затем удаляет старый ключ.
3. Telegram: BotFather выдаёт новый BOT_TOKEN при отзыве старого, поэтому безостановочная параллельная проверка двух токенов обычно невозможна. Сначала подготовить доступ к Cloudflare, инструменты обновления секретов и безопасное окно обслуживания. Владелец отзывает токен в BotFather и вводит новый в секреты; оператор сразу обновляет Worker и локальное секретное окружение, проверяет getMe и выполняет pnpm webhook. Повторно открыть Mini App: подписи старых сеансов станут недействительны. Проверить доставку /start и отсутствие растущей очереди webhook. Рабочий код не содержит токенов, поэтому откат к старому коду не требует возвращать отозванный ключ.
4. WEBHOOK_SECRET заменять согласованно в Worker и регистрации Telegram webhook; ожидающие обновления не удалять.

Самостоятельно создавать или отзывать пользовательские ключи эта доработка не пытается: нужны действия владельца в Cloudflare, Supercell и BotFather. До готовности замены рабочие ключи сохраняются. Перед миграциями использовать D1 Time Travel/экспорт, зафиксировать версию Worker; старые таблицы и привязки миграция 0005 не удаляет. При откате кода новые таблицы оставить.
