# Доступ к Clash API с Workers

Clash API проверяет исходящий IP по списку, заданному для ключа на [портале Supercell](https://developer.clashofclans.com/). Обычный Worker не даёт постоянный исходящий IP. Успешный локальный запрос ещё не означает, что тот же ключ заработает после деплоя.

Свой gateway и прямой доступ — два варианта ниже. Отдельный режим `royaleapi` и результаты его проверки описаны в [сравнении подключений](connection-options.md); пока он не включён.

Для собственного подключения есть два режима:

- `direct`: Worker отправляет `COC_API_TOKEN` только на официальный адрес `https://api.clashofclans.com/v1`. Нужен подтверждённый способ выхода с разрешённого IP. Для обычного Workers этот вариант сам по себе проблему IP не решает.
- `gateway`: Worker обращается к вашему серверу с постоянным IP. В Worker хранится `COC_GATEWAY_TOKEN`, а ключ Supercell остаётся на сервере. Чужому прокси ключ Supercell не передаётся.

В `gateway/server.ts` есть небольшой сервер для второго варианта. Он разрешает только чтение игрока, чтение клана и проверку игрового токена. Произвольный адрес передать ему нельзя. Перенаправления запрещены. Для запросов есть таймаут и ограничение числа одновременных соединений.

## Поднять свой gateway

Потребуется уже доступный сервер с постоянным публичным исходящим IP, Node.js 24 и HTTPS-домен. Бесплатность такого сервера проект не предполагает. Если сервера нет, сначала нужно решить этот вопрос; оплачивать сервис ради запуска бот не будет.

1. Добавьте исходящий IP сервера в ключ на портале Supercell.
2. Положите на сервер файл `gateway/server.ts`.
3. Создайте вне Git файл `.gateway.env`, доступный только владельцу:

   ```dotenv
   COC_API_TOKEN=ключ-с-портала-supercell
   COC_GATEWAY_TOKEN=случайный-секрет-минимум-32-символа
   PORT=8788
   ```

   Секрет можно получить командой `openssl rand -hex 32`. Не вставляйте его в issue, README или команду в общем терминале.

4. Запустите сервер от отдельного пользователя:

   ```bash
   chmod 600 .gateway.env
   node --env-file=.gateway.env gateway/server.ts
   ```

   Для постоянной работы используйте systemd или другой менеджер процессов. Сервер слушает только `127.0.0.1:8788`.

5. Поставьте перед ним HTTPS reverse proxy. Например, Caddy:

   ```caddyfile
   clash.example.com {
       request_body {
           max_size 1KB
       }
       reverse_proxy 127.0.0.1:8788
   }
   ```

   Не включайте запись тела запросов и заголовка Authorization. Ограничьте входящий трафик и настройте обновления сервера. Проверка игрового токена проходит через ваш gateway, поэтому его владелец должен быть доверенным.

6. В `wrangler.toml` задайте:

   ```toml
   COC_TRANSPORT = "gateway"
   COC_API_BASE_URL = "https://clash.example.com/v1"
   ```

7. Сохраните **тот же** секрет gateway в Worker:

   ```bash
   pnpm exec wrangler secret put COC_GATEWAY_TOKEN
   ```

   `COC_API_TOKEN` в Worker при этом не нужен. После смены настроек выполните деплой. Не используйте HTTP и не отключайте проверку TLS.

Проверка настоящего gateway, IP allowlist и успешного ответа `verifytoken` остаётся обязательной перед первым запуском с игроками. Локальные тесты используют подставные ответы и не подтверждают доступ к Supercell.
