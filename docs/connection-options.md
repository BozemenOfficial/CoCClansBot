# Подключение Clash API: результаты проверки

Проверено 10 ноября 2026 года. Для опыта был развёрнут отдельный `coc-clans-connection-lab` в реальном Cloudflare Workers. Рабочий Telegram-бот, его секреты и D1 для опыта не использовались.

Ключа Clash API у владельца проекта пока нет. Поэтому все сетевые проверки выполнялись без действительного ключа; для тела `verifytoken` использовались только синтетические `00000000` и `11111111`. Это проверка маршрутов, а не завершённая проверка игровых функций.

## Выбор для этого проекта

При бюджете $0 первый кандидат для следующего испытания — **оставить бота и D1 на Cloudflare и использовать RoyaleAPI с отдельным ключом Supercell**. Прокси доступен непосредственно из Workers; своего сервера не потребуется. Его актуальная бесплатность, SLA и корректность успешного `verifytoken` ещё не подтверждены. Оператор прокси будет участвовать в обработке ключа и проверочных токенов игроков.

Для большего контроля над секретами и инфраструктурой подходит **тот же Worker + собственный gateway на сервере с закреплённым исходящим IP**. Ключ Supercell остаётся на своём сервере, Worker хранит только секрет gateway. Бесплатный вариант зависит от получения Always Free VM Oracle; платный VPS требует бюджета. До получения реального ключа ни один вариант нельзя считать проверенным для безопасной привязки.

Переносить всего бота с уже работающих Workers и D1 сейчас незачем: это добавит работу с хранилищем и запуском процесса, а условие разрешённого IP всё равно останется.

## Что испытано запросами

Итоговая серия: 125 сетевых наблюдений — 60 запросов из среды разработки, 60 внешних запросов из настоящего Worker и 5 обращений Worker к IP-echo. Для каждого API проверены GET профиля, GET клана и два POST `verifytoken`, по пять повторов. Отдельно выполнены 17 проверок Node gateway.

| Маршрут из реального Worker | Пробы | Ответы | Медиана ответа |
| --- | --- | --- | --- |
| Прямо в Supercell | 20 | 20 × `403 Missing authorization` | 49 мс |
| Через RoyaleAPI | 20 | 20 × `403 Missing authorization` | 99,5 мс |
| Через маршрут ClashKing `/proxy/v1` | 20 | 20 × `401 Authentication token missing` | 53 мс |

Это время **отказов в авторизации**. Оно не измеряет скорость загрузки настоящих профилей и не определяет победителя по производительности. Замеры сделаны из одного узла Cloudflare DFW и не подтверждают доступность из всех регионов.

В пяти запросах к IP-echo возвращался один публичный IPv6. Резервирование статического IPv4 этим опытом не подтверждено. Наблюдаемый адрес нельзя брать в разрешённый список ключа в качестве гарантированного адреса Workers.

У Supercell и RoyaleAPI в этих отказах были `Cache-Control: public max-age=600`, `CF-Cache-Status: DYNAMIC`, без `Age`. Признаков ответа из Cloudflare-кеша в серии не было. По ошибкам авторизации нельзя подтвердить отсутствие кеширования успешной проверки токена. Для этого нужен отдельный опыт с действительным ключом и чередованием правильного и неправильных игровых токенов.

Node gateway был запущен в облачной среде на loopback, затем остановлен:

- Клиент без секрета gateway получил `401`.
- Запрос к постороннему маршруту получил `404`.
- 15 разрешённых GET/POST дошли до настоящего Supercell API и получили `403` с недействительным синтетическим ключом.
- Ответы gateway имели `Cache-Control: no-store`.

Это подтверждает авторизацию и маршрутизацию нашего gateway. Внешний HTTPS, постоянный IP VPS и связка Worker → внешний gateway в этом опыте не проверялись.

## Сравнение практических вариантов

| Вариант | Основание | Условие запуска | Вывод |
| --- | --- | --- | --- |
| Workers → Supercell напрямую | 20 реальных проб из Worker | Действительный ключ и подтверждённый разрешённый исходящий IP | Доступность API есть; постоянный исходящий адрес не установлен. Не выбирать случайно измеренный IP как постоянный. |
| Workers → RoyaleAPI → Supercell | 20 проб из Worker, документация оператора | Отдельный ключ с IP из документации; доверие оператору | Первый кандидат для теста без своего VPS. Успешная авторизация, проверка владения и условия сервиса пока открыты. |
| Workers → ClashKing `/proxy/v1` | 20 проб из Worker; маршрут найден в исходниках приложения ClashKing | Авторизация ClashKing | Без токена провайдера маршрут возвращает 401. Его публичная статистика не заменяет проверку владения. |
| Workers → свой gateway → Supercell | 17 проверок нашего gateway; внешнего VPS нет | Сервер, HTTPS и постоянный исходящий IP | Больше контроля над ключом; собственный сервер придётся обслуживать. |
| Бот целиком на VPS | Архитектурная оценка | Сервер с постоянным IP, адаптация D1/SQLite и запуска процесса | Рабочий вариант, но перенос всего бота не нужен для устранения текущего ограничения. |
| Gateway на Oracle Always Free | Документация Oracle; VM не создавалась | Регистрация, доступная бесплатная машина и закреплённый IP | Кандидат под $0, но есть нехватка свободных ресурсов и изъятие простаивающих VM. |
| Gateway на домашнем устройстве | Архитектурная оценка; ПК пользователя недоступен | Устройство постоянно включено, подходящий исходящий IP | Для ручного теста возможно; постоянство IP и доступность зависят от провайдера и домашней сети. |
| Cloudflare Workers VPC / Tunnel | Документация Cloudflare; сеть не создавалась | Своя сеть/узел и права на её подключение | Туннель даёт путь к своей инфраструктуре; сам по себе не создаёт сервер с постоянным исходящим IP. |
| Cloudflare Gateway + dedicated egress | Документация Cloudflare; услуга не подключалась | Дополнение к Zero Trust Enterprise | Технически решает вопрос адреса, но не подходит под бюджет $0. |
| Cloudflare Containers | Проверена документация, контейнеры не разворачивались | Отдельная конфигурация сети | Подтверждённой гарантии бесплатного закреплённого исходящего IP не найдено; перенос в контейнер сам по себе не закрывает вопрос. |
| Render Free | Документация, сервис не создавался | Общие исходящие CIDR-диапазоны, ограничения бесплатного сервиса | Не подтверждено, что диапазоны подходят ключу Supercell. Dedicated IP требует Pro и доплаты; Free засыпает после 15 минут без входящего трафика. |
| Railway | Документация, сервис не создавался | Pro для static outbound IP | Есть предусмотренный способ закрепить исходящий IPv4, но это платный тариф. |
| Koyeb Free | Документация, сервис не создавался | Гарантированный исходящий IP не подтверждён | Бесплатная машина не решает требование IP автоматически. |
| Google Cloud Free Tier VM | Документация, VM не создавалась | Бесплатная вычислительная квота, отдельная оплата IPv4 | При $0 не подходит: внешний IPv4 стандартной VM стоит $0,005/час после одного бесплатного часа в месяц. |
| Обычный VPS с публичным IPv4 | Документация, покупок не было | Платный сервер, закреплённый адрес, HTTPS | Предсказуемый путь для своего gateway при появлении бюджета. Точный состав цены нужно проверять для выбранного тарифа и региона. |

Цена $0 относится только к доступным бесплатным квотам и не гарантирует бессрочную доступность сервиса. Никакие платные ресурсы, тарифы или дополнительные аккаунты во время опыта не подключались.

## Что подготовлено в коде

Есть явный транспорт `royaleapi` с единственным разрешённым адресом `https://cocproxy.royaleapi.dev/v1`. Он использует отдельный `COC_API_TOKEN`; произвольный домен с этим ключом конфигурация не принимает. Перенаправления блокируются вручную, чтобы ключ не ушёл на другой адрес.

Рабочая конфигурация остаётся `COC_TRANSPORT = "disabled"`. Для будущего теста RoyaleAPI нужно будет явно задать:

```toml
COC_TRANSPORT = "royaleapi"
COC_API_BASE_URL = "https://cocproxy.royaleapi.dev/v1"
```

Ключ сохраняется отдельно через Wrangler secrets. Само наличие режима не означает, что проверка владения через провайдера уже подтверждена.

## Следующий опыт с настоящим ключом

1. Создать отдельный ключ на портале Supercell. Для RoyaleAPI в документации оператора сейчас указан `45.79.218.79`; сверить его перед созданием ключа.
2. Получить настоящий профиль по известному Player Tag. Проверить тег, ник и клан, а также соответствие схеме приложения.
3. В личном чате проверить свой игровой API Token: неправильный A → `invalid`, правильный → `ok`, неправильный B → `invalid`, правильный снова → `ok`. Каждый ответ должен относиться к текущему телу запроса, а не предыдущей проверке.
4. Проверить отсутствие кеширования `verifytoken` и сохранения тела/токенов в логах. Не сохранять игровые токены в артефактах опыта.
5. Проверить отказ для занятого аккаунта, лимиты попыток, ошибки API и таймауты.
6. В тестовой Telegram-группе проверить права `can_manage_tags`, тег обычного участника, пропуск администратора, смену ника и Cron.
7. Подтвердить условия и доступность выбранного посредника. При проблемах с проверкой владения оставить привязку отключённой; чтение профиля не заменяет доказательство владения.

## Проверка кода

`pnpm check` прошёл: TypeScript, ESLint и 60 тестов. Новые тесты проверяют авторизацию стенда, запрет произвольных адресов, отсутствие пересылки секрета стенда и ограничение режима RoyaleAPI его HTTPS-адресом.
